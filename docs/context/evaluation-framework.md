# Evaluation Framework

A consistent way to judge ideas so we compare them fairly and don't chase novelty. Score each criterion roughly **Low / Medium / High** and explain in a sentence. Don't pretend to numeric precision.

## Criteria

### Value
| Criterion | Question |
|-----------|----------|
| **Problem severity** | How painful is this for the owner, staff or customers today? Do they already spend time or money on it? |
| **Client-visible benefit** | Would an owner notice and understand the value without us explaining it? |
| **Willingness to pay** | Is there a believable price a small business would pay, monthly or one-off? |
| **Breadth** | Does this apply to many similar businesses, or only one? |

### Cost and feasibility (for a solo operator)
| Criterion | Question |
|-----------|----------|
| **Build effort** | Time to a first working version for the first client |
| **Repeatability** | How much effort for the second and tenth client? Can it be templated? |
| **Ongoing maintenance** | What breaks, how often, and who gets the call? |
| **Running costs** | Per-client monthly cost (tools, usage, hosting) vs. what we can charge. See `pricing-and-service-models.md` |
| **Service model fit** | Does it work as managed, client-owned, or both? What would we charge in each? |
| **Dependencies** | Reliance on third-party platforms, APIs or policies that can change |

### Risk
| Criterion | Question |
|-----------|----------|
| **Privacy and data** | What customer data is handled, where is it stored, who can access it? |
| **Compliance** | Consent, messaging, consumer, payment or sector rules involved? (Seek professional advice when it matters) |
| **Reputational** | What happens to the client's brand if it misbehaves or is wrong? |
| **Owner adoption** | Will the owner actually use or tolerate it? |

### Strategic fit
| Criterion | Question |
|-----------|----------|
| **Leverage** | Does it build on what we already do, or open follow-on opportunities? |
| **Recurring revenue** | Can it become a retainer or subscription? |
| **Differentiation** | Does it set us apart from DIY website builders and generic platforms? |

## Always compare against

1. **Do nothing**: what's the cost of leaving the problem alone?
2. **Low-tech fix**: a process or habit change, a template, a checklist.
3. **Off-the-shelf tool**: an existing product the client could simply subscribe to.
4. **Custom build**: only justified when the above fall short.

## Output

Conclude an evaluation with: a **recommendation** (pursue / explore further / park / reject), the **key assumptions** it rests on, and the **cheapest next step** to test them.
